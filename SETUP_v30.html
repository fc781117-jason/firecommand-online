1｜找出固定正式網址

先到 Vercel Dashboard（控制台），選擇原本的 FireCommand 專案。

  1. 查看專案的 Overview（總覽），或左側／上方 Settings（設定）→ Domains（網域）。
  2. 找出對應 Production（正式環境） 的固定網址。截圖中的網址含一串部署識別，可能是某次部署的專用網址；正式網址以此頁顯示為準。
  3. 把完整網址貼進本指南最上方欄位，再按「套用網址」。後續需要的完整網址與主機名稱會自動分開列出。

使用同一個固定網址完成 Google、Firebase 與 Vercel 設定。網站更新後也從該網址開啟。

2｜確認同一個 Firebase 專案及 Google 用戶端

程式目前連到的 Firebase 專案 ID 是 firecommand-online。

  1. 開啟 Firebase Authentication 登入方式。若連結帶到專案選擇，選擇 firecommand-online。
  2. 左側選 Security／Build（安全性／建構）→ Authentication（驗證）；中央選 Sign-in method（登入方式），再點 Google。
  3. 確認 Enable（啟用） 已開啟。展開 Web SDK configuration（Web SDK 設定），複製 Web client ID（網頁用戶端 ID）。格式以 .apps.googleusercontent.com 結尾。不要複製 Web client secret。
  4. 若這個區塊沒有顯示，開啟 Google Cloud → Google Auth Platform → Clients（用戶端）。確認頂端專案仍為 firecommand-online，選擇既有的 Web application（網頁應用程式） 用戶端。
  5. 若有多個 Web 用戶端，使用 Firebase Google 登入所指定的同一個。先對照 ID；不能只憑名稱相似任選。

Client ID 是辨識網站的公開代碼。Client secret、OpenAI 與 Gemini API key 則是機密，無須傳給我。

3｜Google Cloud 加入正式網站
  1. 在上一步的 Web 用戶端詳細頁找到 Authorized JavaScript origins（已授權的 JavaScript 來源）。
  2. 點 Add URI（新增 URI），填下列完整來源；不含路徑：https://你的正式網站
  3. 按頁面下方 Save（儲存）。

此版 Google Identity Services 使用回呼取得 credential。此流程不需要新增自訂登入接收頁。原本 Firebase 備援登入所需的 Authorized redirect URIs（已授權的重新導向 URI） 請保留：https://firecommand-online.firebaseapp.com/__/auth/handler

若 Google Auth Platform 的 Audience（目標對象） 顯示 Testing（測試），請確認內測帳號已列在 Test users（測試使用者）。不要為了測試任意變更整個專案的公開狀態。

Google 官方設定文件

4｜Firebase 加入授權網域
  1. 回到 Firebase → Authentication → Settings（設定）。
  2. 選 Authorized domains（授權網域），按 Add domain（新增網域）。
  3. 填下列主機名稱，這次不含 https://，也不含路徑：你的正式網站
  4. 按 Add（新增）／Save（儲存）。原有 firebaseapp.com、web.app 等網域保留。

Firebase Google 登入官方說明

5｜Vercel 填入登入用戶端 ID
  1. 到 Vercel 選原專案，進入 Environment Variables（環境變數）。依控制台版本，它可能直接位於左側，或在 Settings（設定） 內。
  2. 先搜尋 GOOGLE_WEB_CLIENT_ID。已有就按該列右側 ⋯ → Edit（編輯），沒有才按 Add New（新增）。
  3. Name／Key（名稱） 填 GOOGLE_WEB_CLIENT_ID；Value（值） 貼上步驟 2 的完整 Web client ID。
  4. Environments（環境） 勾 Production（正式）。若確實要用預覽環境內測才另勾 Preview，且該網址同樣須被授權。
  5. 按 Save（儲存）。這時舊部署還不會取得新值；完成步驟 6 的新部署才會生效。

Vercel 官方環境變數與重新部署說明

6｜上傳 v30 並重新部署

依您截圖已有 GitHub＋Vercel 的方式，建議使用電腦完成：

  1. 解壓縮 firecommand_v30_online_release.zip，打開資料夾。正確的一層會直接看到 index.html、assets、api、server、firebase、vercel.json。
  2. 到原本 GitHub 儲存庫，確認是 Vercel 連接的正式分支及原專案根目錄；不要另開同名儲存庫。
  3. 檔案列表上方點 Add file（新增檔案）→ Upload files（上傳檔案）。拖入解壓後該層的檔案與子資料夾，覆蓋原有同路徑檔案。不要只上傳 ZIP，也不要多包一層 v30 資料夾。
  4. 在 Commit changes（提交變更） 的說明填 Update FireCommand to v30。沿用既有更新流程；若分支受保護，建立分支與 Pull Request 後再合併。
  5. 到 Vercel 的 Deployments（部署），確認這次提交出現新部署，狀態為 Ready（就緒），且是 Production。若剛才只改環境變數，找正式部署右側 ⋯ → Redeploy（重新部署）。
  6. 從固定正式網址開啟首頁，確認標題顯示 v30。再開本頁的「檢查此站登入設定」。

v30 的 Firestore Rules 與 v29 相同。已成功發布 v29 規則可沿用；若仍用更舊規則，Firebase → Firestore Database → Rules（規則），以包內 firebase/firestore.rules 全文更新後按 Publish（發布）。

GitHub 官方上傳檔案說明

7｜檢查並完成第一次登入
  1. 在正式網站開啟 /login-help.html，按「檢查此站登入設定」。
  2. 若顯示「尚未設定」，回到步驟 5，核對名稱、Production 與新部署是否正確。若顯示已取得 client ID，只代表網站讀得到設定；仍需實際登入驗證。
  3. 按「返回系統首頁」。應出現 Google 官方登入按鈕。以 Safari 或 Chrome 直接開啟，不從舊的 firebaseapp.com 錯誤分頁重整。
  4. 選原本使用的同一 Google 帳號。若成功登入但顯示待審核，這是 FireCommand 帳號啟用流程，請以原管理員帳號至「帳號管理」檢查。
  5. 登出再登入一次；在 iPhone Safari 測試，最後再測兩個已核准帳號的資料同步。

AI 設定：沿用已可用服務，控制反應時間

您的截圖顯示實際使用 openai / gpt-5.4-mini。v29 原始程式的未設定預設值則為 gpt-4.1-mini。正式站若已有 OPENAI_MODEL，該值優先；v30 不會覆寫您的 Vercel 設定。

本次建議先以已成功呼叫的 gpt-5.4-mini＋low 推理完成內測。官方文件確認此模型支援結構化輸出及推理強度；這不等於已驗證每種消防口述的辨識正確率。先前回覆列出的未來日期不適合作為查核日期，本文件統一以 2026-09-10 為準。模型官方規格

新增或編輯的路徑與步驟 5 相同，完成後必須重新部署。金鑰取得位置：OpenAI API keys、Google AI Studio API keys。API 用量與聊天訂閱分別管理；不要把 ChatGPT Plus 或 Gemini 聊天額度當作本 App 的 API 額度。

  1. 登入 App → SOP → 初 → 部署 → 文字回報。
  2. 展開「AI 服務與備援設定」，按「檢查 AI 設定」。這只檢查設定是否存在。
  3. 選 OpenAI，輸入測試句並辨識；核對畫面底部實際服務與模型。再選 Gemini 重測相同句。
  4. 需要較深推理時可把 low 改 medium，重新部署後測相同句的等待時間與正確性。若要比較更高模型，可用已在帳號開通的 gpt-5.4 做小量對照，不宜只看世代名稱。

本版備援條件仍是連線、配額、逾時與輸出格式失敗；不是模型自行宣稱低信心就自動升級。每次最多 3 次服務嘗試，模型階段總預算約 48 秒；網路驗證另計。現場若不等候，可修改原文取消尚未回傳的辨識，再使用本機整理或手動新增。
