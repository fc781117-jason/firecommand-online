FireCommand v34 更新方法

本包使用原本的 GitHub、Vercel、Firebase 與 Google 登入設定。不要建立新專案，也不要重設 Client ID 或環境變數。

步驟一｜先備份 GitHub

  1. 登入 GitHub。
  2. 開啟原 FireCommand Repository：fc781117-jason/firecommand-online。
  3. 確認目前正式分支名稱；本包製作時遠端正式分支為 main。
  4. 記下更新前最新 Commit，發生問題時可在 Vercel 回復該次部署。

步驟二｜上傳完整專案包

  1. 解壓縮 firecommand_v34_github_upload.zip。
  2. 將解壓後資料夾內的檔案與資料夾上傳到原 Repository 根目錄，保留 assets、api、firebase、server、tests 的結構。
  3. 遇到同名檔案時以本包版本取代。不要刪除 GitHub 上本包沒有包含、且由您自行新增的正式設定檔。
  4. Commit 訊息可填：Update FireCommand to v34。

若 GitHub 網頁一次拖放整個資料夾無法正確保留目錄，請改用 GitHub Desktop，把解壓後內容複製到本機 Repository 後 Commit、Push。

步驟三｜等待 Vercel 更新

  1. 登入 Vercel Dashboard。
  2. 進入 FireCommand 專案 → Deployments。
  3. 等待本次 GitHub Commit 顯示 Ready。
  4. 開啟正式網址，頁首應顯示 v34。

步驟四｜發布 Firestore Rules

網站先上線也能使用；發布本包 Rules 後，後端會一併限制人數只能是空白、0或0–99整數。

  1. 登入 Firebase Console｜Firestore Rules。
  2. 開啟本包的 firebase/firestore.rules，全選並複製內容。
  3. 貼到 Firebase 的 Rules／規則 編輯器。
  4. 按 Publish／發布。
  5. 本版沒有要求修改 firebase/storage.rules，不要為了本次更新放寬照片權限。

步驟五｜用練習案件驗收






回復方式

若網站更新後出現問題，到 Vercel → Deployments 找更新前正常版本，點右側選單並執行 Redeploy；GitHub 則回復更新前 Commit。Firestore Rules 可在 Firebase Rules history 回復前一版。
