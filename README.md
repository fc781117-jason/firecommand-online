# FireCommand v28｜反覆語音回報與人車圖面同步

交付日期：2026-09-07。基準為本工作區已交付的 v27 完整原始碼。這是可供部署驗收的新版本；本次未更新正式站、Google Console 或 Firebase 規則。

## 每次都用同一入口

進入案件後，按頁首「語音／文字快速回報」。實戰與練習使用同一個元件、解析器、資料結構及交易流程。部署頁與人員統計頁也有入口。

1. 說出本次新增或修正，或以鍵盤語音／文字輸入。
2. 瀏覽器語音結束後自動顯示辨識差異；鍵盤輸入則按「辨識本次回報」。
3. 查看原文、校正名稱、原數值 → 新數值及總人數；如有同名編組，點選此次對象。
4. 勾選核對後按「確認登錄並同步」。成功後清空本次輸入，直接說下一次回報。

| 回報範例 | 系統處理 |
| --- | --- |
| 但水4人報到 | 顯示「但水 → 淡水」；確認後登錄4人，未說位置就放待部署區 |
| 主委6人第三面搜救 | 校正「主委 → 竹圍」，登錄人數、任務與示意位置 |
| 淡水人數修正為6人 | 沿用原編組ID，將人數設為6；不是再加6 |
| 淡水新增2人 | 原有人數增加2；預覽會顯示修正後總數 |
| 竹圍A組4人報到；竹圍B組3人報到 | 建立兩組；後續可指定A組或在歧義提示中選組 |
| 竹圍移至第二面 | 移動已登錄人員，保持人數與任務 |
| 淡水11移至第一面 | 移動同一車輛，既有水線連結保留 |
| 淡水61供水給淡水11；淡水11第一面出兩線 | 車對車供水及兩條到第一面的水線；重複相同絕對回報不再新增 |
| 淡水11水線改接第三面 | 來源只有一組終點時沿用既有水線ID改接；多終點須到圖面選線 |

分隊、數字、句型在裝置上解析，不使用 OpenAI 做自由推測。本版有指定的語音別字字典與相似名稱候選；**不是任意口語都能完整理解**。瀏覽器 SpeechRecognition 是否提供、是否需網路，依瀏覽器與裝置；不支援時使用手機鍵盤的麥克風。

## 哪些資料會一起變

人員直接寫入原本 `crews`，車輛寫入 `vehicles`，水線寫入 `hoses`。原有人數卡、部署圖、概要、續報摘要及新產生的報告，都從這些共用資料讀取。歷史已輸出的報告不會被追溯修改。舊部署文字保留，快速回報啟用後概要改以最新結構化資料為準。

新增 `intakeEvents` 保存原文、校正、選擇、操作者、前後值與復原紀錄。時間軸另有簡短登錄摘要。原有手動修改、拖曳、建物旋轉仍可使用。

練習的出題、暫停、倒數與評分保持 v27 規則。快速登錄人車資料不會自行取代「我的判斷與處置」回應，也不會因為新增4人就推斷PAR完成。單純人員在冊數不等於安全清點結果。

## 更新步驟

1. 保留原正式部署作為回復點；將本資料夾完整更新至原 Vercel 專案。
2. 保留現有 Firebase 設定及原有 `OPENAI_API_KEY`、`OPENAI_MODEL`、地圖環境變數。新增登入設定依 **LOGIN_v28.md**，優先使用既有 Google OAuth Web client ID。
3. 部署 Firestore 規則：`firebase deploy --only firestore:rules --project firecommand-online`。
4. 重新發布 Vercel，確認頁首 v28，`/api/maps-config` 的版本為28。所有協作者需更新至 v28，以使用同一套資源版本檢查。
5. 依 **VALIDATION_v28.md** 做正式環境驗收，尤其是 iPhone 真機登入、收音、兩帳號同步。

無須重建實戰案件或搬移既有人車資料。本版保留原有本機儲存鍵。v27 練習模式、SDS 及角色協作操作說明見 README_v27.md；其文字轉圖建立流程以本版快速回報取代。

## 邊界與復原

- 每次最多3,000字、30段、100筆變更；人數0–99、同一起終點水線0–6條。未提及的人數、位置與任務不補寫。
- 目前定位至建物第一至第四面，屬示意位置。樓層、消防栓精確定位、多終點選線、不明條件與否定語句會要求補充或使用原有表單。
- 同一分隊有多個編組時不自動合併；「全隊共幾人」需要分組更正。休息、撤離、PAR等仍使用原有專用操作，以保留其連動流程。
- 同一筆提交重試不重複寫入；重新開始一筆「新增2人」是新的增量，仍須核對預覽。
- 雲端一次交易寫入變更與紀錄。若預覽後有人修改人車、水線或建物框，拒絕覆蓋並要求重新辨識。舊版協作者新增的重複編組不能靠新版本全面防止，因此需全員更新。
- 「最近回報與復原」保留前後值；相關資料已再修改或出現新的依附水線時不直接回復，以免破壞他人的新操作。
- 線上版需連線才能確認交易。網路失敗保留草稿，不顯示已儲存；尚未做離線多人合併佇列。
