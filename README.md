# FireCommand v26｜現場效率、圖文一致與協作演練版

本版以 v25 正式版為基準，保留案件概要、SOP、Google Maps、人車水線、建物作戰圖、AI 建議、進度報告與檢討報告，新增以下功能。

## v26 更新重點

1. 建立案件時輸入的建物用途、建築構造、樓層與起火樓層會自動帶入「建」SOP；初報火煙、觀察面向與煙量會自動帶入「火」SOP，不必重複填寫。
2. 修正舊版工廠／倉庫案件可能被誤帶成住宅用途的相容資料；開啟舊案件時會依案件類型校正顯示，儲存 SOP 後寫回正確用途。
3. 關係人提示精簡為「尋找到關係人後會展開填寫相關資料」；危險物採相同的漸進展開邏輯。
4. 部署頁新增「第一時間快速文字紀錄」。還來不及畫圖時，可先記錄各面、人車、水線與任務，文字會同步顯示於繪圖區及 SOP 確認資料。
5. 新增部署圖文一致性檢查。若文字與圖面關鍵資料不一致，儲存作戰圖或完成部署檢查時顯示「圖面與紀錄不符」；使用者選擇「我已經確認，以圖面為主」後，系統清除舊文字並保存圖面摘要。
6. 新增「AI 依圖面整理部署摘要」。AI 僅整理已有的結構化人車、水線、危害與建物圖示；AI 無法使用時會自動改用本機結構化摘要，不阻斷現場操作。
7. 破門流程拆分為「準備破門時間」與「破門完成時間」，兩個時間會分別進入狀態卡、續報稿及確認資料。
8. 戰情頁預設只顯示兩列：「戰情回報｜火勢狀況」與「戰情回報｜傷患者」。點選後才展開，兩者互斥；送出後自動收合。傷患者另有獨立事件時間與回報單位。
9. Google 登入改為 popup 流程並明確採用 LOCAL persistence，避免 iOS／內嵌瀏覽器跨網域回跳時因 `sessionStorage` 分割或失效而卡在 Firebase 英文錯誤頁；App 內另有重新登入與重新載入復原提示。
10. 新增「練習模式」：可用個人設定、AI 自動設置或案例檔案建立虛擬案件；房主產生 6 碼房號，其他同大隊使用者可選擇角色加入。
11. 練習房支援真人協作、AI 角色補位、開始／暫停、自動發布下一情境、手動發布下一情境及教官臨時事件。預設腳本用完後，AI 教官可持續產生新事件；AI 暫時不可用時仍有本機備援事件。
12. 實戰案件與練習案件在首頁分流，所有虛擬資料標記為練習，不混入實戰案件列表。

## 現場操作建議

- 開案時先填已知的建物與火煙資料；進入 SOP 後只補尚未確認的欄位。
- 第一時間沒空繪圖時，先在部署頁輸入文字並儲存；開始繪圖後，文字會固定顯示在建物作戰圖上方供核對。
- 部署完成時按「完成部署／一致性檢查」。若系統提醒不符，先返回修改；只有確認圖面是最新事實時才選擇以圖面為主。
- 「準備破門時間」代表開始準備／決策的時間；實際完成後另填「破門完成時間」。
- 進入戰情頁後，先選火勢狀況或傷患者，填寫並送出；送出後表單會自動收合，維持畫面簡潔。

## 練習模式使用方式

1. 首頁切換至「練習模式」。
2. 房主選擇個人情境、AI 自動設置或上傳案例檔案，設定難度與角色後建立房間。
3. 其他人輸入 6 碼房號並選擇演練身分加入；房主可按「AI 自動補位」補齊缺少角色。
4. 房主開始演練後，系統依難度每 30／45／60 秒發布動態情境，也可手動發布或插入臨時情境。
5. 參與者使用與實戰相同的 SOP、戰情、部署、人車及報告功能完成判讀與協作。

## 登入錯誤說明

畫面若出現 `Unable to process request due to missing initial state`，代表舊的 Firebase 登入回跳頁依賴的暫存狀態已被 iOS、內嵌瀏覽器、儲存空間分割或時間清除；這不是案件資料遺失。v26 不再啟動 redirect 登入，改用 popup，因此新登入不應再停在該回跳頁。

若使用者仍開到舊的 Firebase 頁面：

1. 按瀏覽器「上一頁」或關閉該登入頁，返回 FireCommand。
2. 按「重新登入」；若仍失敗，用 Safari 直接開啟正式 App 網址。
3. 不要從數日前仍停留在 `firebaseapp.com/__/auth/handler` 的舊分頁進入 App。

## 發布與必要設定

1. 將本資料夾內容覆蓋 GitHub 專案根目錄，提交至 Vercel 使用的 Production Branch。
2. 部署更新後開啟 `https://firecommand-online.vercel.app/api/maps-config`，確認 `enabled: true` 及 `version: 26`。
3. 將 `firebase/firestore.rules` 重新發布至 Firebase。v26 規則只對 `mode == "practice"` 的案件開放同大隊啟用帳號協作；實戰案件仍維持原本的指揮角色寫入權限。
4. 確認 Firebase Authentication 的 Authorized domains 包含正式 Vercel 網域。
5. 練習情境 AI、動態事件與圖面摘要沿用 `OPENAI_API_KEY` 及 `OPENAI_MODEL`。案例檔案上限 3MB，支援 TXT、MD、JSON、CSV、PDF 與圖片。
6. Google Maps Billing、Maps JavaScript API、Places API（New）、Geocoding API 與 `GOOGLE_MAPS_BROWSER_KEY` 沿用既有設定。

## 重要界線

- AI 文字只作為訓練與勤務撰寫輔助，不取代現場指揮官判斷、正式救災命令或事故調查。
- 上傳案例檔案會送至系統設定的 OpenAI API 進行情境分析；上傳前應移除姓名、電話等可識別個資。
- 圖文衝突確認屬於操作防呆，不代表系統已能從任意點位完全理解所有戰術語意；應由使用者確認最新事實。
- v26 沿用既有資料集合，更新前仍建議備份 Firebase 專案及正式部署版本。
