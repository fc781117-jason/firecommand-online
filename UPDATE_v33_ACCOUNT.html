FireCommand v33｜帳號管理更新辦法

這是一個接續 v32 的局部更新包，由您自行上傳；下載壓縮檔不會自動更新網站。本次沒有修改 Firebase 設定、Firestore Rules、既有帳號、案件資料或正式部署。

先確認版本：請先打開您目前的 FireCommand 網站，確認頁首為 v32。如果已由他人更新過 index.html 或 assets/app.js，不要直接覆蓋：先比較差異或提供最新原始碼再合併。本更新是基於 GitHub 原專案 fc781117-jason/firecommand-online 的 main、commit e7c37b46f888cee850a025d22e536be2c1e5545e 製作。

一、壓縮檔裡有什麼

相對於專案根目錄用途
index.html帳號管理入口、篩選與確認視窗、v33 資源引用
assets/app.js列表、即時更新、管理動作與交易檢查
assets/account-admin-core.js搜尋、單位樹、篩選和狀態轉換
assets/account-admin.css手機版與桌面版帳號卡片樣式
tests/account-admin-vnext.test.cjs可選；本機自動測試
UPDATE_v33_ACCOUNT.html本更新說明

絕對不要因這份壓縮檔刪除原專案的其他資料夾。尤其保留 firebase/firebase-config.js、firebase/firestore.rules、api/ 與 Vercel 環境變數原狀。

二、推薦：用 GitHub Desktop 手動上傳並先看 Preview

  1. 開啟 GitHub，登入管理 FireCommand 原專案的帳號，確認可看到 fc781117-jason/firecommand-online。不要建立新的 Firebase、GitHub 或 Vercel 專案。
  2. 在電腦開啟 GitHub Desktop 官方下載頁，安裝並用同一個 GitHub 帳號登入。若已安裝則直接開啟。
  3. GitHub Desktop 選 File → Clone repository，從 GitHub.com 選 fc781117-jason/firecommand-online，選您知道位置的本機資料夾，按 Clone。如果已經在 GitHub Desktop 開啟此專案，先按 Fetch origin，確認目前沒有未上傳的其他修改。
  4. 在 GitHub Desktop 專案左上方 Current Branch，由 main 建立新分支，例如 feature/account-management-v33；確認「Branch from main」。若 main 已不等於上方基準 commit，請先不要覆蓋 app.js。
  5. 把下載的 firecommand_v33_account_update.zip 解壓縮。打開解壓後的資料夾，把裡面的 index.html、assets、tests、UPDATE_v33_ACCOUNT.html 複製到剛剛 Clone 的專案資料夾，遇到相同檔名選「取代」，但不要刪除原本資料夾中其他檔案；不得在專案中多包一層 firecommand_v33_account_update。
  6. 回到 GitHub Desktop → Changes，逐一核對只出現表格列出的檔案（包含新增檔案），不應看到 Firebase 設定、規則或案件資料。Summary 輸入 Account management v33，按 Commit to feature/account-management-v33，再按 Publish branch。
  7. 登入 Vercel Dashboard，進入原 FireCommand 專案 → Deployments，找到這個分支對應的 Preview（前提是原 GitHub 專案已與 Vercel 連線）。按 Preview 網址；若看不到 Preview，先到 GitHub 專案 → Pull requests → New pull request，選這個 feature branch，再檢查 Vercel 的 Preview 狀態。
  8. 先依第三部分在 Preview 驗收。Preview 與正式站網址不同：Google 登入可能因 Preview 未設定 OAuth 來源而回傳 origin_mismatch，這不是帳號管理程式錯誤；不要為了測試 Preview 任意公開或改弱登入／資料規則。若 Preview 不能安全登入管理員，就先用本機測試與 UI 靜態檢查，待您確認部署方式後再安排正式環境驗收。
  9. 只有在確認 Preview 無問題、您決定上線後，再由您本人在 GitHub Pull Request 按 Merge pull request。原專案若以 main 連動 Vercel，Vercel 的 Deployments 應出現新的 Production 部署並顯示 Ready；若沒有自動部署，請先檢查原專案連線，避免誤建立其他專案。

三、上線前後檢查

  1. 頁首應顯示 v33；一般使用者不應看到「帳號管理」。最高管理員能看到入口，待審人數大於 0 時顯示待審 Badge，管理區預設收合。
  2. 展開後檢查四張狀態卡片；用姓名片段、Email、中隊名稱、大隊、分隊、職稱搜尋；搭配單位、角色和狀態篩選，結果數應正確，無資料時應顯示提示與清除條件。
  3. 待審卡片只顯示「核准啟用」，啟用卡片只顯示「停權」，已停權卡片顯示「恢復啟用」。點選後先確認提示內容，取消不應改資料；建議使用專門的測試帳號驗收，不要直接拿真實勤務帳號測停權。
  4. 用 iPhone Safari 測搜尋鍵盤、篩選對話框、觸控按鈕和縱向頁面；用第二個帳號確認沒有管理員操作權限、原本登入及案件仍可使用。
  5. 如果頁首仍為 v32，先確認 Vercel 最新 Production 是 Ready、瀏覽的是原固定網址，然後重新開網頁／關閉 iPhone 主畫面舊分頁再開。本版新增檔案以 ?v=33 引用，無新增 Service Worker。

四、撤回及尚未提供的功能

若更新後異常，保留 feature branch，在 GitHub 對 v33 變更開新的還原 Pull Request 或使用 Vercel 原有的安全回滾流程；不要手動刪除 Firestore 使用者。本次僅新增局部 UI，未新增「不通過／REJECTED」、批次核准、永久審核歷史、新的角色權限矩陣；因舊帳號模式尚未定義這些動作的授權及資料保留政策。既有的 lastAdminAction 僅記最後一次操作，不是完整審計記錄。
